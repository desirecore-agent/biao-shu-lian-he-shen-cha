# Tender Review Team

## Release 0.2.3

Add model-service prerequisites, operator responsibility for terms/licensing/costs, evidence-based readiness checks, and stopping before affected external calls when prerequisites are unavailable. These are team execution instructions; static checks do not demonstrate live enforcement or real-tender acceptance. See [usage](USAGE.md) and [shared rules](shared/rules.md).

Five-role review assistance: Lead, Requirements, Commercial, Visual and independent Evidence review. Since 0.2.0, members use clear natural-language assignments and outcome quality criteria and choose their methods and useful delivery formats. Version 0.2.1 adds transparent portrait avatars for the team and all five members.

Start with [usage](USAGE.md). Read the [project guide](PROJECT.md), [shared rules](shared/rules.md) and [quality rubric](shared/quality-rubric.md) for responsibilities, good/bad examples and focused correction guidance.

Review findings should be important, supported, locatable and actionable. Unreadable sources and unfinished work remain visible. Ordinary review requires no fixed input/output schema or six-file pack. [Legacy contracts](shared/contracts/README.md) are optional exports only.

Install through the published market release and review team rules. Source locks protect install identity; they do not establish business accuracy. Existing recorded testing used synthetic materials. The selected model may process supplied documents/images; extra-service transmission requires authorization. The team assists human review and does not authenticate documents or guarantee award.

## Member display default

Version 0.2.2 declares `memberDisplay: "nested"` in `team.json`: team members appear under the leader, initially collapsed. Explicit user preferences take priority. Install this release only after the DesireCore platform adds support for this field; older clients reject it during team schema validation.
